# 场所变动影子试点

本目录对应[试行标准](../../docs/auv-interest-push-standard.md)。评估器只根据结构化输入返回建议动作。它不读取手机、接触用户资料或调用推送服务。真实入口的可见权限、来源核实、去重版本和最晚有用时间应由可信后台准备。开放与关闭在合成样本中分别覆盖。

在此目录运行：

    node --test policy.test.mjs
    node replay.mjs

回放报告输出到终端，汇总 200 对合成事件与用户偏好，样本说明见 [fixtures-notes.md](fixtures-notes.md)。报告的“拟推一致率”比较现在发或计划发送的动作与预期。分钟边界在单元测试验证。合成数据用结构化标注验证规则分流，后续上线验收仍依赖独立人工标注和真机到达记录。延迟的单条通知与用户预约摘要用 scheduleKind 区分。

[线上只读检查](inspect-possible-pairs.sql)按能查看的角色、明确地点订阅、已启用的兴趣提醒和有效期汇总可能候选，仅返回计数。设备计数按现有 Worker 的 90 天有效窗口统计，服务商受理为全类型历史记录，与手机显示分开计。

现有审核 RPC 把关闭类事件写为面向全体的公共通知。独立兴趣试点只接受明确属于订阅范围的来源，防止重复。生产数据暂时缺少可信的「恢复开放」事件类型，不能把关闭事件自然到期当作重新开放。采用新来源之前需给审批明确的开闭类型、有效时间及订阅范围。

接入真实队列前，在实际发送时重新核对来源版本、可见权限、开关、已读、静默和期限。在同一事务原子检查并预留当日兴趣预算，同一摘要组只占一次。当前评估器只拿到决策时预算快照。将来需要用独立人工标注集报告 95% 与 80% 试点目标的样本数、置信区间和问题分类。手机端验收沿用两账号测试，核对服务端设备登记、站内通知、个推受理、手机显示和跳转。

排程输入须由后台按用户时区计算。quietUntil 表示当前静默结束，digestAt 取考虑未来静默周期后的可用摘要时刻。收藏本身和数据库默认开启的收藏匹配字段不能单独作为发送授权。
