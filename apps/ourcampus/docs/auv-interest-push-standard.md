# OurCampus AUV 兴趣与及时推送试行标准

日期 2026-11-26。本文定义候选分析、收件资格、发送时机与验收口径。表中的时间、频率和样本门槛是试点参数。

## 1. 把各入口统一成事件

每条业务变化生成一条带来源的事件。后台保留来源类型、记录 ID、版本、发生时间、最晚有用时间、可见范围、核实状态和原始入口。能从业务表确认的事实直接读取。按来源明确允许的处理目的、可见范围和保留期限。获准分析的公开内容才交给 AI 抽取。接收兴趣推送的开关负责是否接收，来源能否处理需独立明确。一个事件分析一次，然后按多位用户的已授权偏好匹配。

| 入口 | 可用信息 | 初始处理 |
| --- | --- | --- |
| 大厅回复、私信到达 | 业务表中的发送关系和接收者 | 直接给当事人的事务提醒。私信正文留在会话，系统通知可用通用文案 |
| 官方公告、活动、场所状态 | 发布者、适用地点、生效时间、当前版本 | 校验发布权限和状态，匹配明确订阅 |
| 公开大厅消息、报修、失物招领 | 获准分析的脱敏短文本，发布范围和来源链接由后台保管 | 识别事件、否定、地点、时间和原文证据。单条公开线索保留待核实状态 |
| 用户发布的图片、海报 | 在来源可见范围内的获准图片及 OCR 证据 | 后台异步处理。图片里识别出的日期和地点仍需校验，可先用于搜索 |
| 个人课表、收藏、订阅与反馈 | 已授权的地点、时段、类别与开关 | 只为本人增加匹配条件。课表匹配尽量用时间和地点，全文留在原权限边界 |

模型候选至少包含事件类别、是否为新变化、时间状态、地点候选和可回到原文的证据。时间状态区分即将发生、正在发生、已结束、明确否定和不明。后台验证格式、证据、地点及时间，登记可信来源。只有后台能写入核实状态、收件人及发送计划。无法确认的字段允许留空。来源中出现的文字指令按普通内容处理。

## 2. 按人匹配，留下推荐理由

1. 后台先确定谁有权看原始记录。事务通知走明确写在业务表里的当事人关系。兴趣推荐需要本人开启，并以本次操作时有效的偏好为准。
2. 强相关来自本人订阅的地点与主题、本人收藏且选择接收更新的地点、本人正在处理的报修，或本人主动开启的失物线索匹配。先做精确匹配，再在获准范围内用同义表达和语义检索找候选。
3. 弱相关来自明确授权后的重复行为或语义相似，第一版用于站内排序。一次浏览和一次未点击都不改变订阅。用户标记「不相关」或关闭某类提醒时，立即更新偏好并复核待发送记录。未开兴趣提醒的新账号从无兴趣推送开始。
4. 每条推荐在站内显示可理解的理由，例如「你订阅了图书馆开放时间」。置信度来自人工标注集上的检验，不能以模型自己填的数字作为放行依据。

## 3. 决定是现在发、稍后发，还是只放站内

| 判断 | 渠道与时效 |
| --- | --- |
| 有人回复本人、本人报修状态变化 | 开启对应通知时及时进入队列。短时间内同一会话的多条消息可合并；事务消息单独计算频次 |
| 时间敏感且已核实，明确命中订阅 | 在用户允许的时间内及时推。优先发布会改变当下行动的更新，例如即将封闭的已订阅入口 |
| 已核实但不急，且有兴趣依据 | 放站内，或在用户选择的时间发摘要。摘要发送前重新检查每条事件 |
| 相关但尚待核实，例如失物相似线索 | 站内标记「可能相关」，展示出处。涉及危险或应急的信息进入人工复核，由可核实官方流程处理 |
| 闲聊、历史复述、否定、时间不明、过期、撤回、已读、权限或偏好失效 | 依类型跳过即时推送，保留明确的拦截原因 |

建议试点默认安静时间为 22:30–07:30（北京时间），用户可修改。兴趣类系统提醒每日最多 2 次，摘要计 1 次。在用户允许的窗口内，选择仍有用的最早时刻。最晚有用时间应留出合理的行动时间，例如从报名截止时刻减去完成报名需要的时间。等到安静时间结束时如果已过期，取消系统提醒。事务消息使用各自开关，用户设置的静默应继续生效。紧急官方通知另走授权的发布规则。

同一个人、同一业务事件和同一有效版本只生成一条提醒。单条大厅消息由回复、订阅和兴趣同时命中时，已有共用去重键，定向回复优先。跨多个帖子疑似同一事件先归并候选，找到核实来源后再使用统一事件 ID。推送前重新核对读状态、可见范围、订阅、来源版本和有效期。撤回后取消尚未提交的提醒。对已提交供应商的通知，点击时仍重新验证权限和来源有效性，锁屏仅显示必要提示。重试也使用原本的去重键，服务商的有效期以剩余有用时间为上限。

例子。假设校方发布「图书馆西翼今天 15:30 关闭，北翼照常开放」。订阅图书馆开放变化的同学在关闭前收到提醒。只关注篮球的同学按原有公开范围看到公告即可。若输入是「上周西翼关过，今天没关」，后台标为否定或历史，不生成关闭提醒。

## 4. 用可复现的数据验收

- **事务与权限用例**。用测试账号覆盖回复本人、作者本人、无关第三人、无订阅、重叠订阅、退订、跨账号与跨区、已读、撤回、重复和过期。关键用例全部通过。出现越权、撤回后继续推或重复系统推送时，暂停对应路径并复核。
- **语义试跑**。用独立的至少 200 对「事件 × 目标用户」人工标注结果做影子试跑，只记录原本会采取的动作。至少包含 50 条能区分否定、旧事、疑问、转述和恶意指令的困难例。标注包括「允许看到」「相关」「应该现在推／稍后发／只站内／跳过」。训练和验收按事件与时间分开，避免同一事件的改写落入两组。
- **试点准入**。新加的 AI 兴趣类别达到拟推样本至少 60 条、拟推准确率至少 95%、应立即提醒的样本命中率至少 80%，同时报告样本数和置信区间。把权限与失效事件误推单列为零容忍。达标后先限一类已核实来源、小范围测试账号。低于门槛时继续作为站内候选。
- **时效**。试点目标是即时类的「业务事件写入到个推受理」P95 不超过 2 分钟。按类型同时记录站内入库、设备登记、服务商受理、手机到达和点击定位成功。离线、静默和未登记单列。真机到达需要设备侧证据，服务商受理单独计数。
- **长期价值**。跟踪有用、不相关、退订、关闭通知、过期率、重复率和每人每日发送量。点击率只做辅助。小样本阶段重点看逐条原因，防止为了点击而增加频次。
- **最小日志**。记录事件 ID 和版本、配置版本、匹配理由、决定的渠道、安排时间、结果及拦截原因，使用受限权限查看。记录排队时点、供应商受理时点及设备回报时点，用于定位延迟。调试日志使用必要的内部标识及错误类别，避免存储消息正文、联系方式或设备凭据。

## 5. 对接 OurCampus 的顺序

1. 先验收已上线的大厅回复和明确地区订阅。前端确认服务端登记成功后再显示「已登记」，把手机权限、个推 CID 和服务端登记分开排查。先用两个本人测试账号跑通站内、受理、真机到达和跳转。 [回复迁移](supabase/22-hall-reply-notifications.sql)
2. 在现有分析和推送任务之间记录动作建议，先影子运行。复用已有的用户本人偏好、订阅、失物匹配、来源有效性及发送前复核。大厅分析当前实现有中国时区每月 1,000 次模型调用限制。先按来源和事件过滤，图片较慢则异步处理。 [现有分析 SQL](https://github.com/zhchunyu/Our-Campus/blob/8d874689be9caad3b8a0976ddf0c9b2cf3eb3e37/apps/ourcampus/docs/supabase/20-hall-proactive-analysis.sql#L147-L258)
3. 第一类兴趣推送使用已核实的地点或活动变化与明确订阅。公开大厅和识图先提供可搜索的候选；逐类验收后再决定是否开放更广的提醒。[离线回放](../scripts/interest-pilot/README.md)检验事件分流、静默时间与频控。

## 研究依据

- Motz 等人在高校试验中，只向临近截止且确实尚未提交的学生提醒；对照组收到课程公告。前者平均收到的通知更少，作业提交比例提高约 3.7 个百分点。启示是先找到能验证的待办状态，给用户留出行动时间，再按真实行动评估价值。 [IEEE TLT，2021](https://doi.org/10.1109/TLT.2021.3064613)

- LinkedIn 把已处理、过期、重复和整体发送负担纳入统一的通知决策，并区分站内与系统渠道。AUV 可先用一套后台规则统筹不同入口。 [KDD 2018](https://www.kdd.org/kdd2018/accepted-papers/view/near-real-time-optimization-of-activity-based-notifications) · [LinkedIn 工程说明](https://www.linkedin.com/blog/engineering/messaging-notifications/air-traffic-controller-member-first-notifications-at-linkedin)
- Pinterest 在仅手机推送组的 A/B 测试中，相对旧系统发送量减少 6%，点击率上升 11%，日活增长 1%。校园试点可借鉴发送预算和整体效果的思路，具体频次在自己的场景中验证。 [Pinterest KDD 2018，表 1](https://doi.org/10.1145/3219819.3219906)
- Fitz 等人的 237 人随机现场实验比较了原样发送、定时批量发送和完全关闭，支持把可预期的摘要作为选项。Lin 等人的研究发现，一部分用户希望保留某些通知，即使不需要点开。AUV 同时看主动反馈和关闭通知。 [Fitz 等，2019](https://scholars.duke.edu/publication/1402953) · [Lin 等，CHI 2021](https://people.cs.nycu.edu.tw/~armuro/pubs/lin-et-al-2021-chi.pdf)
- Geifman 和 El-Yaniv 的选择性分类研究讨论了允许模型保留判断时，误判风险和覆盖量的取舍。AUV 对不确定样本可以先站内、延迟或人工复核，接受多少案例要用校园验收数据测。 [NeurIPS 2017](https://proceedings.neurips.cc/paper/2017/hash/4a8423d5e91fda00bb7e46540e2b0cf1-Abstract.html)
