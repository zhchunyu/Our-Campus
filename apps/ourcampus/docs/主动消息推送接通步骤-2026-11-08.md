## 1. 创建个推应用

打开 https://dev.getui.com/ ，登录或注册，新增“消息推送”服务，创建 Android 应用：

| 项目 | 填写 |
| --- | --- |
| 应用名称 | OurCampus |
| Android 包名 | cn.edu.sxau.campustwin |
| 平台 | Android |

官方提供免费基础推送。先按基础功能接通，不需为此购买 VIP；具体频次、厂商通道限制以账号控制台为准。认证、应用资料和厂商审核由账号持有人完成。

创建后在应用配置中找到同一应用的 AppID、AppKey、MasterSecret。AppID 可提供给开发者用于客户端配置；另外两个直接保存到后台，不要在聊天或仓库中发送。

## 3. 配置安卓公开参数并重新打包

由开发者把 AppID 写入忽略 Git 的 android/push.local.properties：

```properties
GETUI_APP_ID=2Oxl7C9Hw18vahrvjaYBP1
VIVO_PUSH_ENABLED=false
VIVO_APP_ID=
VIVO_APP_KEY=
```

AppKey、MasterSecret 不进入 APK。

如果需要 iQOO/vivo 在划掉后台后也能稳定接收，继续在个推中配置对应 vivo 厂商应用，并将其客户端 AppID/AppKey 填入相应字段后启用 VIVO_PUSH_ENABLED。vivo 的 AppSecret 只保存在服务端或服务商控制台。当前代码已预留 vivo 模块，但没有完成真实厂商配置；免费基础通道的存在不能替代厂商开通。

更新包必须使用手机现有 App 对应的原证书签名。本机缺少签名材料，参考既有《Android-1.17-原签名打包与发布交接》，由原打包电脑构建。不要把另一台电脑生成的临时 debug 证书当成可覆盖安装的升级包。

## 4. 手机开启并登记

1. 安装正确配置、同签名的新版 APP，登录自己的账号。
2. 进入消息中心，阅读推送说明并开启系统通知；允许 Android 通知权限。
3. 手机生成接收标识后，APP 自动把当前安装与当前账号登记到 Supabase。
4. 检查 campus_push_devices 出现当前设备的 enabled=true 记录；仅有通知权限但没有设备记录仍不算接通。

退出或切换账号时必须沿用现有停用设备绑定逻辑。通知点击只传消息 ID，详情仍由当前登录账号回查。

## 5. 分别验收两种提醒

仅面向自己指定的测试账号验证：

- 前台：保持 APP 打开，产生一条新的本人通知，出现横幅；覆盖页面关闭或回到前台后仍能看到待显示的新提醒。
- 后台：按 Home 退到桌面后产生新通知，手机通知栏出现消息。
- 划掉后台：完成厂商通道配置后单独验证，不能用前台通过代替。
- 点击通知：回到对应消息，确认收件人正确，打开详情后才标已读。
- 重复刷新、重复回执、账号切换和已读通知不应导致重复提醒或串号。

服务商 accepted 仅表示受理，实际送达以手机通知栏及服务商到达统计为准。尚未登记设备、配置厂商通道或完成手机验收前，不宣称后台推送已经成功。
